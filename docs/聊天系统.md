# ChatGPT 对话系统使用说明

## 启动

后端使用 Conda `project` 环境：

```bash
cd backend
conda activate project
pip install -e .
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

前端：

```bash
npm install
npm run dev -- --host 0.0.0.0 --port 4180
```

默认数据库为本机 MySQL：

```text
mysql+pymysql://root:your-password@127.0.0.1:3306/chat_workspace?charset=utf8mb4
```

## 用户端

- `/`：开始使用入口。
- `/register`：注册账户。
- `/login`：登录账户。
- `/chat`：ChatGPT 风格聊天工作区。
- 侧边栏“项目”可创建项目，项目卡片上的加号可创建项目内对话。
- 输入框可切换文本/图片模式并选择已启用模型。
- 图片模式支持选择参考图；发送时会调用图片渠道的生成或编辑接口。
- 文本模式也支持一次选择多张图片（单轮最多 8 张）：浏览器会将本地像素缩放并压缩为
  JPEG Data URL；当所选渠道只接受 PNG 时则保留/编码为 PNG。视觉数据随 `media_inputs`
  放入本次文本请求，文本模型可直接读取图片；服务端仅持久化资产 ID，不把 Base64 像素
  写入消息、请求事件或日志。
- 文本模型请求会自动附带 `generate_image` 工具。模型决定生图时，界面会在同一条
  对话中显示工具状态和生成图片，文本流仍保持 SSE 增量更新。
- 对不产生原生 `tool_calls` 的文本模型，服务端还会注入平台工具协议 Prompt；模型
  输出的平台工具标签会由服务端截获并执行，不会显示在聊天正文中。
- 对话顶部更多菜单可归档、删除或导出。
- 已归档对话会在用户端刷新后恢复到“更多”列表；重新生成会复用原 assistant 消息，不重复增加用户提示词。
- 指定模型没有启用渠道时会提示渠道不可用并保留当前对话，不会静默切换到其他模型。

用户发送文本或图片请求前必须拥有有效授权；无授权账户仍可查看已保存内容。生成图片资源通过当前用户的 `Authorization: Bearer TOKEN` 请求头访问，前端先以带鉴权的 Blob 请求加载，再创建临时对象 URL，不把 JWT 放入图片地址。

## 真实数据与页面状态

用户工作区不再内置默认会话、固定消息或离线回复。页面数据来源如下：

| 资源 | 真实 API | 页面行为 |
|---|---|---|
| 会话 | `GET/POST /threads`、`PATCH/DELETE /threads/{id}` | 列表、创建、重命名、归档和删除均以服务端结果为准 |
| 归档会话 | `GET /threads?include_archived=true`、`PATCH /threads/{id}` | 仅展示真实归档记录，支持恢复 |
| 项目 | `GET/POST /projects` | 展示真实项目并在 API 成功后更新 |
| 模型 | `GET /models` | 按文本/图片能力展示已启用模型 |
| 授权 | `GET /me/entitlement` | 普通用户仅在有效授权时可发起模型请求 |
| 文本对话 | `POST /threads/{id}/messages/stream` | 使用 SSE 流式展示真实上游结果 |
| 图片生成/编辑 | `POST /threads/{id}/image-generations`、`POST /assets/upload` | 支持直接生图、参考图编辑及文本模型工具生图 |

文本模式视觉请求的 `media_inputs` 元素格式如下（最多 8 张，单张编码载荷约 1.5 MiB，
整轮约 3 MiB）：

```json
{
  "type": "image",
  "data_url": "data:image/jpeg;base64,...",
  "asset_id": "上传接口返回的资产 ID",
  "mime_type": "image/jpeg",
  "width": 1280,
  "height": 900,
  "detail": "auto"
}
```

`detail` 会按所选文本模型的 `input_image_detail` 能力发送 `auto`、`low` 或 `high`。
管理员可在渠道“能力映射”中配置通用策略，或在模型 ID 下配置更精细的限制，例如：

```json
{
  "supports_input_image": true,
  "max_input_images": 4,
  "input_image_max_bytes": 1200000,
  "input_image_detail": "high",
  "supported_input_image_mime_types": ["image/jpeg", "image/png"],
  "vision-model": {
    "capabilities": ["text"],
    "supports_input_image": true,
    "max_input_images": 2,
    "input_image_detail": "low"
  }
}
```

发送前会根据模型能力检查视觉开关、图片数量、MIME 与解码后字节数；服务端仍会再次
校验这些约束以及资产归属。未配置 MIME 列表时默认接受 JPEG/PNG；将
`supports_input_image` 设为 `false` 可明确关闭该模型的识图能力。

浏览器编码策略与参考工作台一致：原图先限制在 20 MiB 内，最长边按 1600/1280/1024/800
阶梯缩放，透明背景填白后以 JPEG 质量阶梯压缩。后端会校验 Data URL、Base64、JPEG/PNG
文件头、图片资产归属以及渠道配置的 `supports_input_image`、张数、MIME 和字节上限。

会话、归档、项目、模型和授权分别管理自己的请求状态，一项失败不会把其他已加载数据清空：

- **loading**：显示对应的“正在加载…”状态，并禁用依赖该资源的操作。
- **empty**：API 成功且列表为空时显示“还没有对话”、“暂无已归档对话”、项目空态或“未配置可用模型”，不填入演示记录。
- **error**：API 失败时显示明确的加载失败信息，不把失败当作空列表。
- **retry**：会话、归档、项目、模型和授权错误状态都提供对应重试入口。

创建、重命名、删除、归档和恢复操作只在真实 API 成功后更新列表。发送或重新生成失败时会移除临时消息或恢复原回复，不生成可继续操作的本地会话。
重新生成的旧正文与来源请求作为同一版本恢复，刷新、复制与三种导出不会看到失败请求的部分草稿。同一 assistant 消息同一时间只允许一个活动重新生成；并发请求返回 HTTP `409`，防止跨渠道流交错覆盖。
账户区仅在真实登录用户存在时展示账户信息，头像使用真实显示名的首字符，不再引用固定头像资源。
用户管理和使用记录也分别区分加载中、真实空数据与加载失败；失败时隐藏统计和分页，并提供重试，不用 `0` 或“暂无记录”代替接口错误。复制按钮仅在浏览器 Clipboard 写入成功后显示完成状态。

当没有启用且具备文本能力的真实渠道时，文本发送和重新生成接口返回 HTTP `503`；该检查在写入用户/助手消息、创建请求记录或修改旧回复之前完成。显式指定的渠道不存在、已停用或与模型能力不匹配时返回 `422`。

### 暂不展示的能力

尚无完整真实 API 或未形成端到端调用链的入口已从页面隐藏，包括：图片库、资料库、日程、插件、Codex 独立页、公开分享、赞/踩反馈、语音输入/语音模式、帮助、用户设置、管理端设置和非图片文件上传。对应真实接口完成后再恢复展示。

## 管理端

管理员登录后访问 `/admin/model-channels`、`/admin/users`、`/admin/usage`。

初始管理员由 `CHAT_ADMIN_EMAIL` 和 `CHAT_ADMIN_PASSWORD` 配置；公开代码不包含默认生产凭据。

```text
CHAT_ADMIN_EMAIL=admin@example.com
CHAT_ADMIN_PASSWORD=change-me-now
```

模型渠道页面配置 OpenAI-compatible Base URL、API Key、渠道类型（官网版/Codex GPT）、模态和优先级；模型列表不再手工填写，保存后由服务端从渠道的 `/v1/models` 自动同步。
模型 ID 包含 `image` 时归类为图片模型，其余归类为文本模型，并可用
JSON 能力映射标注每个模型的文本/图片能力、Responses 传输或图片编辑 JSON 传输。
用户管理页面可按月开通、暂停、恢复或撤销权限；使用记录页面支持用户/模型/模态/日期筛选、分页和 CSV 导出。
渠道页面支持从 `/models` 同步模型及能力覆盖；服务端同时支持
`/chat/completions`、`/responses`、`/images/generations` 和 multipart `/images/edits`。
进入 `/admin/model-channels` 后，页面会立即同步所有已启用渠道，并每 60 秒通过本站
管理 API 再次请求上游 `/models`。首次调用会延迟到当前事件循环末尾，从而避免 React
StrictMode 开发预演产生重复请求；页面卸载会清理首次任务、定时器和自动请求。自动同步与
手动同步共享按渠道锁，服务端以 Condition 单航班状态唤醒所有等待者并复用并发同步结果。渠道行显示最近同步时间和
失败状态，同步期间禁用该行的配置操作。浏览器始终只接收掩码密钥；Base URL 禁止携带
用户名或密码，更换服务地址时必须重新输入 API Key。

## OpenAI-compatible 协议契约

渠道的 Base URL 会规范化为 API 根路径（例如 `https://HOST` 自动补成
`https://HOST/v1`）。服务端请求统一携带 `Authorization: Bearer TOKEN`，其中
`TOKEN` 只保存在服务端加密字段中。

### 模型列表

`GET /v1/models` 返回常见的 `{ "data": [{ "id": "MODEL" }] }`，也兼容直接返回
模型数组。管理端点击“同步模型”会以远端 ID 集合刷新渠道模型；“管理模型”弹窗通过只读的
`/admin/model-channels/{id}/remote-models` 获取远端集合，再勾选要展示的模型并保存。模型 ID
包含 `image` 时归类为图片模型，其余归类为文本模型；仍可在渠道的 `capabilities` 中显式配置
`{"MODEL": ["text"]}` 或 `{"MODEL": ["image"]}` 覆盖能力。

### 文本流

默认调用 `POST /v1/chat/completions`，请求字段包括：

```json
{
  "model": "MODEL",
  "messages": [{"role": "user", "content": "PROMPT"}],
  "stream": true,
  "stream_options": {"include_usage": true},
  "temperature": 0.7,
  "top_p": 0.9,
  "max_tokens": 4096,
  "reasoning_effort": "medium",
  "response_format": {"type": "json_object"},
  "tools": [{"type": "function", "function": {"name": "generate_image", "parameters": {}}}],
  "tool_choice": "auto"
}
```

除 `model/messages/stream/stream_options` 外的可选字段仅在客户端设置时发送；
`response_options` 可透传供应商扩展字段，但其中的 `reasoning_effort` 或 `reasoning`
不会覆盖经请求 Schema 校验的思考等级。流式响应按 SSE `data:` 帧解析，读取
`choices[].delta.content`、分片 `choices[].delta.tool_calls`、末尾
`choices[].finish_reason` 与 `usage`。系统向浏览器转发的事件包括
`message.created`、`message.delta`、`search.started`、`tool.started`、`image.created`、
`tool.completed`、`message.completed`、`request.usage` 和 `error`。

当本轮带图片时，`messages` 最后一条用户消息的 `content` 使用多模态数组。Chat
Completions 形态为 `image_url` + `text`：

```json
{"content":[
  {"type":"image_url","image_url":{"url":"data:image/jpeg;base64,...","detail":"auto"}},
  {"type":"text","text":"请描述这张图"}
]}
```

若渠道能力映射配置 `{"_text_endpoint":"responses"}`，同一输入会转换为 Responses 的
`input_image` + `input_text`。图片不会被改发到图片生成接口；未显式配置视觉能力的历史
文本渠道按兼容模式允许 JPEG/PNG 输入，也可通过渠道能力中的
`supports_input_image: false` 或模型级对象关闭视觉输入。

### AI 回复展示与联网搜索

仅官网版渠道在联网搜索时可能把内部状态作为文本 chunk 返回，例如
`search("JSON_STRING")slow|QUERY|1` 或省略索引的 `search("JSON_STRING")slow|QUERY`。
服务端使用增量解析器跨 chunk 识别该格式，
将其转换为 `search.started` 事件而不写入 AI 正文。聊天页在等待正文时显示带地球
图标的“正在搜索 QUERY”，收到首个正文 Token 后自动收起。旧消息在 API 读取及导出时
仅在消息当前内容所绑定的根请求来自官网版渠道时清除已保存的完整搜索指令；Codex
渠道中的同形普通正文保持原样。重新生成会原子更新内容来源请求，跨渠道切换后不会受旧
请求干扰；旧数据没有来源元数据时按最新根请求兼容判断。非法、超长或字段不符合约束的
候选按原文保留；无索引格式必须具有明确的行结束符。

AI 文本通过 `react-markdown` 和 `remark-gfm` 安全渲染，支持标题、粗体、列表、链接、
引用、代码块和表格，并忽略模型输出的原始 HTML。模型返回的真实 Markdown 链接显示为
灰色圆角来源标签；平台不为没有 URL 的回复填充来源。整篇回复若被多余的
` ```markdown ` 围栏包裹，会先移除外层围栏再渲染；其他语言代码块仍保持代码样式。
Markdown 远程图片不会自动请求第三方地址，而是显示文字占位，避免跟踪像素或来源泄露。

聊天输入框的“思考”按钮支持关闭、低、中、高、超高五种状态，四个启用等级依次发送
`low`、`medium`、`high`、`xhigh`。该设置同时用于新消息与重新生成；官网版和 Codex GPT
渠道均通过相同 OpenAI-compatible Provider 链传递。图片模式不发送文本思考参数。

若渠道能力配置 `{"_text_endpoint": "responses"}`，文本请求改用
`POST /v1/responses`，将消息转换为 `input`，函数工具转换为 Responses 工具，
并解析 `response.output_text.delta`、`response.function_call_arguments.delta` 和
`response.completed`；思考等级转换为 `reasoning: {"effort": "LEVEL"}`。供应商以 HTTP 200
返回的 `error` SSE 帧也会被标记为失败。

### 文本模型兼容工具协议

部分 OpenAI-compatible 文本渠道会接收 `tools` 字段但始终把工具意图作为普通文本
返回。图片工具可用时，系统会在保留原生 `tools/tool_choice` 的同时添加 System
Prompt，要求模型在需要生图或编辑图时只返回：

```text
<platform_tool_call>{"name":"generate_image","arguments":{"prompt":"完整图片提示词","size":"1024x1024"}}</platform_tool_call>
```

服务端使用增量解析器处理标签，即使开始/结束标签被拆到多个 SSE chunk，也只把普通
文本作为 `message.delta` 发给浏览器。完整工具标签会被隐藏并转换为内部工具调用；
参数继续通过 `GenerateImageToolArguments`、用户资产归属、图片大小、最大工具回合和
最大调用次数校验。若同一轮同时存在原生 `tool_calls` 和平台标签，以原生调用为准。

平台兼容调用使用独立 ID 前缀。下一轮请求会把这类调用和结果转换成普通
`assistant/user` 上下文，并在 System Prompt 中附带已执行结果，兼容拒绝
`role=tool` 的网关，同时避免成功生图后再次调用。真正由 Provider 返回的原生工具
调用仍按 OpenAI 标准消息结构回放。

文本模式上传参考图时，服务端会在对应用户消息后追加
`<platform_attachments>` 元数据，内含真实 `asset_ids` 和可选 `mask_asset_id`。
模型只能复制这些 ID 到 `generate_image` 参数；实际执行前仍会验证资产属于当前用户。
图片尺寸支持 `auto`、兼容固定尺寸以及经过边界校验的 `WIDTHxHEIGHT`，因此工具可
传入当前渠道的 `2560x1440`、`1440x2560`、`3840x2160` 等预设。

### 图片生成与编辑

无参考图时调用 `POST /v1/images/generations`，主要字段为 `model`、`prompt`、
`n=1`、`size`、`quality` 和 `response_format`（`b64_json` 或 `url`）。当前聊天消息
结构只持久化单张结果，因此 `n > 1` 会在请求校验阶段返回 422，避免静默丢弃图片。
返回 `data[]` 中的 `b64_json` 或 `url`，服务端会校验 MIME/大小并保存为用户资产。

图片请求会在服务端统一解析 Prompt 中的输出参数，直接图片模式、图片编辑以及文本模型
触发的 `generate_image` 工具共用同一套规则。当前渠道的常见映射包括：

- `16:9 2K` → `size=2560x1440`
- `9:16 2K` → `size=1440x2560`
- `16:9 4K` → `size=3840x2160`
- `9:16 4K` → `size=2160x3840`
- `高清`、`高画质`、`high quality` → `quality=high`

同时支持 `1:1`、`2:3`、`3:2`、`3:4`、`4:3`、横屏/竖屏、`720P`、
`1080P` 和有界 `WIDTHxHEIGHT`。Prompt 中明确写出的参数优先于请求默认值；未提供
参数时沿用请求值。执行前仍会进行尺寸、质量和资产归属校验。质量参数使用
`auto/low/medium/high`；旧客户端的 `standard/hd` 会分别规范化为 `medium/high`。

带参考图或遮罩图时调用 `POST /v1/images/edits`：标准模式使用 multipart 的重复
`image` 文件字段和可选 `mask` 文件字段；渠道能力可设置
`{"image_edit_transport": "json"}` 以发送兼容网关所需的 JSON 图片数据。用户端
只提交自己拥有的 `asset_ids`，服务端会再次校验归属、文件存在性和总大小。

用户端发起图片请求后立即显示“正在创建图片”圆角点阵卡片；生成成功后卡片替换为
保持原始宽高比的大图预览，并提供下载及消息操作。文本模型开始执行图片工具时也使用
相同占位状态；系统启用“减少动态效果”时保留静态卡片但停止动画。点击停止会同时
停止文本根请求及正在运行的图片工具子请求；同步上游若稍后才返回，服务端会在数据库
行锁下复核状态并丢弃结果，不创建图片资产，也不会把请求重新标记为完成。
前端只有在 `/messages/stop` 返回成功且 `stopped=true` 后才结束本地等待状态并提示“已停止”；接口失败时保留当前流和停止按钮，允许再次操作。

## 时间与时区

- 数据库和后端业务计算继续使用 UTC，权限有效期、请求排序、清理任务及已有数据语义保持不变。
- API 响应中的项目、会话、消息、渠道、用户、授权、用量、导出和审计时间统一转换为带 `+08:00` 偏移的 ISO 8601 北京时间。MySQL 返回的无时区 `DATETIME` 统一按 UTC 解释后再转换，避免发生重复偏移。
- 前端通过 `src/utils/beijingTime.ts` 统一格式化时间，显式指定 `Asia/Shanghai`；页面展示不受浏览器或操作系统时区影响。旧版无偏移 API 字符串仍按 UTC 兼容解析。
- 模型渠道同步时间、用户授权到期时间、使用记录时间以及 CSV 导出均标注并使用北京时间。
