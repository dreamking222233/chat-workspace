## 1. 用户原始需求

> 然后所有页面及数据的时间 都按北京时间显示

## 2. 技术方案设计

### 2.1 时间边界

1. 数据库继续保存 UTC 时间，后端权限判断、过期判断和清理任务继续使用 UTC，避免改变既有数据语义。
2. API 输出的时间必须携带明确时区；MySQL 返回的无时区 `DATETIME` 按 UTC 解释，禁止输出含义不明确的时间字符串。
3. 所有前端可见日期、日期时间、时分秒及 CSV 导出固定使用 `Asia/Shanghai`，不依赖访问设备的系统时区。
4. 管理端日期筛选输入按北京时间自然日解释，再转换为带时区的 API 参数；“至”日期覆盖北京时间当天结束。
5. 页面明确标注“北京时间”，使用户能够识别展示与筛选口径。

### 2.2 核心实现

- 新增前端公共北京时间工具，统一：
  - 将无偏移 API 时间按 UTC 解析；
  - 北京日期、日期时间、时分秒格式化；
  - 北京自然日筛选边界生成。
- 管理端渠道、用户、使用记录页面全部改用公共工具，CSV 与页面保持同一时区。
- 后端增加统一 UTC 规范化/序列化能力，对手写字符串响应补齐 `Z` 或明确偏移，避免浏览器误判。
- 增加与运行机器时区无关的单元测试，并验证日期筛选参数。
