## 发现与处理

- Conda 环境的 `passlib` 与 `bcrypt 5.x` 存在兼容警告，密码实现改为标准库 PBKDF2-SHA256。
- 前端 `4180` 端口曾未加入 CORS，已补充白名单并验证预检请求 `200 OK`。
- 原型阶段使用 `create_all`，已补充 Alembic 初始迁移并将现有 MySQL 标记为 `0001_initial`。
- SSE 生成器原先复用请求依赖的数据库会话，可能导致流返回而正文未落库；已改为独立会话并增加持久化回归测试。
- 重新生成原先通过普通发送接口会重复插入用户提示词；已改为复用目标 assistant 消息的专用流，消息数量保持不变。
- 指定模型渠道缺失时原先可能回退演示模型；现返回 503 并在前端清理乐观消息，只有未配置任何模型且未指定模型时保留演示模式。
- 已归档项目现在不能接收新会话或作为会话归属，用户端刷新后仍可从归档列表恢复。

## 收尾复核

收尾后重新运行后端 7 项 pytest、Python 编译检查、前端生产构建和 Alembic head 检查，均通过；并使用运行中的 Uvicorn + 本地 MySQL 完成一条端到端链路。当前未完成项仅为真实供应商渠道和浏览器像素截图采集，需要部署方提供实际渠道配置和可用浏览器环境。

## 残余风险

- 真实文本/图片供应商需由管理员在模型渠道页面配置有效 OpenAI-compatible 地址和密钥。
- token 字段已持久化并展示；没有供应商 usage 时保持为空，后续可按 Provider 补齐。
- 当前文件存储为本地目录，生产环境建议替换为 S3 兼容对象存储并增加过期清理任务。
- 当前验证以构建、API 集成和响应式源码检查为主；完整 Playwright 像素对比需可用浏览器实例。
