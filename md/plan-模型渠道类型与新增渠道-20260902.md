# 模型渠道类型与新增渠道实施方案

- 功能名称：模型渠道类型与新增渠道
- 日期：20260902
- 任务级别：中型任务（渠道数据模型、管理页面、远端同步、真实渠道初始化与调用验证）
- 当前状态：实施完成，Review 通过

## 1. 用户原始需求

系统中的模型渠道分为“官网版”（具备联网搜索等官网模型能力）和“Codex GPT”（不具备联网搜索能力）。管理端 `/admin/model-channels` 需要维护渠道类型；现有 `http://provider.example:3000` 渠道设为官网版，并新增 `http://provider.example:8080` 渠道，使用给定 API Key，通过 `/v1/models` 同步模型，按 OpenAI 协议验证文本及图片调用。

## 2. 技术方案设计

1. 在 `model_channels` 增加 `channel_type` 字段，取值 `official`（官网版）或 `codex`（Codex GPT），历史渠道默认 `official`。
2. 后端创建、更新、列表响应及数据库兼容启动逻辑支持该字段；保留现有 OpenAI-compatible provider/protocol 字段。
3. 管理页面增加渠道类型选择、列表徽标和编辑回填；自动同步仍每 60 秒执行，并按远端 `/v1/models` 更新模型。
4. 使用后端现有 Chat Completions/Responses 与 Images 适配器，针对两类渠道只标识能力差异，不改变 OpenAI 请求结构。
5. 通过真实管理 API 创建/更新渠道，随后调用同步、测试、文本和图片端点，记录实际模型列表与结果。
