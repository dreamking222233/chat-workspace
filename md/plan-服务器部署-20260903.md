# 服务器部署-20260903 实施方案

## 用户原始需求

连接部署服务器，从公开 GitHub 仓库拉取当前项目，配置并启动前后端服务，包含代码与 `init.sql`。

## 技术方案

1. 确认公开仓库地址和 `main` 分支内容可访问。
2. 通过 SSH 连接部署主机，检查 Ubuntu 版本、权限、磁盘、现有端口和运行时（Git、Python、Node、MySQL/Docker、Nginx）。
3. 在 `/opt/chat-workspace`（可根据服务器现状调整）克隆或更新仓库。
4. 使用独立 Python 虚拟环境安装后端依赖，创建生产 `.env`，不把密钥写入 Git。
5. 初始化 MySQL：优先使用现有 MySQL；没有可用服务时使用 Docker Compose 的 MySQL，并执行根目录 `init.sql` 或 Alembic migration。
6. 安装前端依赖并执行生产构建，使用 Nginx 提供静态文件和 `/api` 反向代理到 Uvicorn。
7. 使用 systemd 管理后端进程，配置开机启动、日志和重启策略；配置持久化 `CHAT_STORAGE_DIR` 保存图片资产。
8. 执行健康检查、登录/API 检查、模型渠道接口检查和前端静态资源检查。
9. 记录部署信息、端口、服务命令和回滚步骤，避免输出或提交凭据。

## 影响范围与风险

- 服务器上的 `/opt/chat-workspace`、systemd 服务、Nginx 配置、数据库 schema 和资产目录会发生变化。
- 需要确认 SSH 账号具备 sudo 权限、服务器网络可访问 GitHub、数据库凭据和模型渠道配置可用。
- 不覆盖已有同名服务或数据；发现冲突时先备份并采用新服务名。
