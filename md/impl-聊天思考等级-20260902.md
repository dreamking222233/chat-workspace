## 1. 实现内容

- 将原布尔思考开关改为等级状态：关闭、低、中、高、超高。
- 点击“思考”按钮展开等级菜单，展示各等级用途；选择后按钮显示当前等级。
- 文本发送和重新生成均传递 `reasoning_effort`：
  - 低：`low`
  - 中：`medium`
  - 高：`high`
  - 超高：`xhigh`
- 图片模式禁用思考等级按钮，避免向图片接口发送文本推理参数。
- 后端 Schema 只接受上述四个值；Chat Completions 发送 `reasoning_effort`，Responses 发送 `reasoning: {effort: LEVEL}`。
- Provider 保留已校验的思考等级，`response_options` 中同名的 `reasoning_effort` / `reasoning` 无法覆盖强类型参数。
- 官网版和 Codex GPT 渠道共用 Provider 适配链，不按渠道类型删减等级。

## 3. 真实渠道验证

- 渠道1官网版，模型 `gpt-5-6`：`low`、`medium`、`high`、`xhigh` 均返回 HTTP 200。
- 渠道2 Codex GPT，模型 `gpt-5.6-luna`：`medium`、`high`、`xhigh` 均返回 HTTP 200；`xhigh` 返回 `reasoning_tokens=10`。`low` 使用 `gpt-5.4-mini` 验证为 HTTP 200。
- 渠道2部分 `gpt-5.4-mini` 高等级测试曾出现上游 30 秒无响应；切换低延迟模型后四档协议均可正常调用，说明等级字段可传输，实际耗时仍取决于模型和上游负载。
