# 模型提供商接入实施方案（v2）

日期：2026-08-30

## 用户原始需求

- 接入两个使用 OpenAI 协议的模型提供商，提供不同的文本和图片模型能力。
- 管理端通过 `/admin/model-channels` 管理渠道和渠道模型；用户在 `/chat` 选择模型并请求。
- 文本模型使用流式响应。
- 图片模式支持图片生成和基于参考图的图片编辑。
- 文本对话自动获得当前系统的生图 tool；模型判断需要生图时调用图片模型，再把结果返回到对话。
- 渠道1（TARGET）由部署配置提供 Base URL 和 API Key；其 OpenAI-compatible 接口包含 `/v1/models`、`/v1/chat/completions`、`/v1/images/generations`、`/v1/images/edits` 和 `/v1/responses`。

## 当前基线

- 后端已有 `ModelChannel`、渠道 CRUD、优先级路由、Fernet 密钥存储、文本 SSE、图片生成和资产保存。
- 文本 Provider 只发送 `model/messages/stream/stream_options`，没有透传可选参数、工具回合或多模态消息。
- 图片 Provider 只支持 JSON 生成；前端上传的资产没有关联到图片请求，图片编辑未接入。
- 渠道模型目前只能由管理员手工录入，缺少从兼容服务 `/models` 同步的能力。

## 技术方案

1. 扩展模型渠道配置：增加模型同步接口和可选的环境变量种子配置，保持第二家供应商通过管理端配置，不硬编码具体密钥。
2. 将 OpenAI Chat Completions 请求建模为可选参数透传：`temperature`、`top_p`、`max_tokens`、`reasoning_effort`、`response_format`、`tools`、`tool_choice`，并兼容供应商返回的 `tool_calls`、usage 和 SSE delta。
3. 统一图片 Provider：生成使用 `/images/generations`；编辑优先使用标准 multipart `/images/edits`，必要时回退兼容供应商接受的 JSON `image` 字段；解析 `b64_json`、URL 和常见响应变体。
4. 扩展资产引用：消息请求携带 `asset_ids`，服务端校验当前用户所有权，将参考图读取为 data URL/文件上传给图片 Provider；生成与编辑均记录 `ModelRequest` 和 `Asset`。
5. 增加生图 tool 编排：向文本模型添加 `generate_image` 函数工具；检测流中的 tool call，执行图片请求，把 `tool` 结果作为下一轮消息重新请求文本模型，最终仍通过 SSE 输出文本和图片事件。设置最大 tool 回合，避免循环。
6. 前端增加参考图预览/移除、图片模式下的生成/编辑请求、模型筛选和 tool 图片事件渲染；保持现有聊天布局与本地演示回退。
7. 增加测试：模型同步、OpenAI payload、SSE tool call、图片生成/编辑 multipart、资产越权、工具回合上限、前端构建。

### 数据库与迁移

- `messages` 增加结构化内容、工具调用标识和资产引用字段；工具消息使用
  `role=tool`、`content_type=tool` 保存，列表接口只返回用户可见消息。
- `model_requests` 增加父请求、回合序号、幂等键和持久化 SSE 事件；根请求汇总
  整次对话的用量，子请求记录每次 OpenAI-compatible 调用，并以唯一索引避免重复。
- `model_channels` 保存每个模型的能力覆盖、同步时间、测试状态和错误信息。
- 生产使用 `alembic upgrade head`；开发启动时对旧 SQLite 表执行幂等字段补齐，
  避免 `create_all` 对已有表不增列的问题。

### 流式与工具状态机

1. `message.created` 创建可见 assistant 占位消息。
2. 消费 Chat Completions SSE，逐段发出 `message.delta`，并合并分片
   `tool_calls`（兼容非流式 JSON 响应）。
3. 对每个合法 `generate_image` 调用发出 `tool.started`，校验参数和资产归属，
   调用图片接口并持久化资产，发出 `image.created`、`tool.completed`。
4. 将 assistant tool call 与 tool result 加入下一轮消息，最多执行配置的回合和
   调用次数；达到上限后以可见错误事件结束，不继续递归。
5. 根请求结束时发出 `message.completed` 与 `request.usage`；断线通过请求 ID 和
   `Last-Event-ID` 重放内存事件或数据库终态。

### URL、资产和回滚

- Base URL 规范化为稳定 API 根路径，缺少版本路径时补 `/v1`。
- 参考资产只接受当前用户拥有的图片文件，校验文件存在、MIME 和总字节数；
  图片编辑通过标准 multipart，兼容渠道可配置 JSON transport。
- 任何 provider/图片失败都将根请求标记为 `failed`，已写入的资产保留引用，
  对话可重试；停止请求标记为 `stopped`。迁移前备份数据库，回滚使用对应
  Alembic downgrade 和文件资产清理脚本。
