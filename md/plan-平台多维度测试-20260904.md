# 平台多维度测试-20260904

## 测试目标

对已部署的 Chat Workspace 平台执行真实端到端测试，覆盖认证与权限、文本模型流式请求、模型渠道同步、图片生成、参考图编辑、资产读写、错误处理、幂等与前端页面表现。

## 测试边界

- 使用公网入口的真实 API；测试账号及管理员账号仅用于测试，不在报告中输出令牌或密钥。
- 测试产生的临时线程、资产和请求记录在验证后清理；不修改生产渠道密钥。
- 图片上游可能受供应商权限限制，记录真实 HTTP 状态和错误，不将失败标记为成功。

## 并行测试分工

1. 认证、权限、模型目录、文本 SSE、停止/重连/幂等。
2. 图片生成、参数解析、资产上传、参考图编辑及错误边界。
3. 前端公网页面、登录/聊天交互、管理端渠道展示与浏览器控制台。
4. 主执行者检查服务健康、数据库/资产持久化、日志、回归测试并汇总。

## 验收标准

- 每个测试记录请求、状态码、关键响应事件和清理结果。
- 区分平台代码问题与上游能力/权限问题。
- 不泄露 API Key、访问令牌或用户密码。
- 形成 `md/impl-平台多维度测试-20260904.md`，并在必要时补充修复提交。

## 测试发现后的修复范围

测试发现图片模型上游失败时，直接生图接口会把助手消息内容写为失败文案，但仍保留 `image` 内容类型。历史会话刷新后，前端将这段错误文案当成图片 URL 读取，最终展示破图。

本轮仅修复该已验证的状态一致性问题，并保留上游失败的用户可见语义：

1. 后端在直接生图失败时将助手消息持久化为文本类型，并映射常见上游图片权限/配额失败文案。
2. 前端为历史异常 `image` 消息添加无图片资产时的文本回退，避免旧记录继续渲染破图。
3. 补充后端失败持久化与前端历史记录回退测试。
4. 完成回归、生产构建与公网复测；若本地和公网结果一致，再部署最小修复。
