## 1. 实现内容

- 按渠道1真实 SSE 格式解析 `search("JSON_STRING")MODE|QUERY|INDEX` 与省略索引的 `search("JSON_STRING")MODE|QUERY` 搜索指令。
- 新增有界、失败时保留原文的增量解析器，支持指令跨任意 Provider chunk 边界分割。
- 搜索指令转换为 `search.started` SSE 事件，前端在正文输出前显示“正在搜索 QUERY”，正文开始后自动收起。
- 新生成的消息、SSE 完成事件和数据库正文不再包含搜索内部协议；历史消息在 API 读取和导出时也会兼容清洗。
- AI 正文使用 `react-markdown` + `remark-gfm` 渲染，支持标题、段落、粗体、列表、引用、代码块、表格和真实链接。
- 链接使用接近官网引用的灰色圆角标签；只渲染模型实际返回的 URL，不生成虚构来源。
- 如上游将整篇答案包在 ` ```markdown ` 中，前后端均会去除这层多余围栏，内部 Markdown 仍按正文渲染；其他语言代码块保持不变。
- Markdown 内联 HTML 被忽略，外部链接使用 `noopener noreferrer`。
- 仅官网版渠道启用搜索指令解析；历史消息也必须能关联到官网版渠道请求才会清洗，Codex 渠道中以 `search(...)` 开头的普通说明文本保持原样。
- 搜索指令对 JSON 字符串、非空查询、`fast/slow` 模式、`1..1000` 索引和 8192 字符上限做严格校验；非法或超长候选按原文保留。
- 修复 `\r\n` 恰好跨 Provider chunk 拆分时的增量解析边界，并以真实 CRLF 样本遍历全部单切分点验证解析等价性。
- SSE 客户端只在事件名、JSON 数据均完整且事件已应用后推进 `Last-Event-ID`，半帧断流会从最后确认事件继续回放。
- Markdown 远程图片不再直接加载，改为无网络请求的文字占位；危险 URL 与原始 HTML 继续由安全渲染策略过滤。
- 每次文本生成或重新生成都会在同一事务中把 assistant 当前内容绑定到对应根 `ModelRequest`；历史清洗依据该请求的实际渠道，不再因同一消息关联过旧官网版请求而误删后续 Codex 正文。旧数据没有来源元数据时，以最新根请求作为兼容判定。
- 重新生成发生 Provider 异常时，后端在同一事务恢复旧正文与旧来源绑定，与前端现有恢复行为一致；页面、复制、刷新和 JSON/TXT/Markdown 导出保持同一版本。
- 对重新生成目标消息加数据库行锁并检查活动根请求；请求创建、清空草稿和来源绑定在一个事务提交。同一 assistant 已有活动生成时返回 409，避免跨标签/跨渠道流交错覆盖正文与来源。

## 5. 二次 Review 后迭代

- 二次 Review 发现同一 assistant 消息“官网版生成后改用 Codex 重新生成”时，旧官网请求会误导历史清洗；现通过 `Message.content_json.response_source_request_id` 原子绑定当前内容来源解决。
- 新增双向跨渠道回归：官网版→Codex 保留同形普通文本，Codex→官网版继续清洗搜索协议；失败重新生成会回滚旧正文与旧来源，并保持消息 API、JSON/TXT/Markdown 三种导出一致。
- 最终真实渠道复测首次捕获到不带 `|INDEX` 的搜索指令；解析器已兼容该变体。无索引格式必须带换行边界，流结束时无换行的歧义候选继续 fail-open。
- 扩展后的有索引/无索引 CRLF 样本均遍历所有单切分点；真实渠道再次返回 `search.started`，SSE 与持久化正文均无内部协议，临时会话已删除。

## 6. 第三轮 Review 后迭代
