# 文本模型兼容工具调用实施记录

日期：2026-09-02

## 任务概述

针对只返回文本、不会生成原生 OpenAI `tool_calls` 的模型，增加 System Prompt 驱动
的平台工具协议。文本模型识别生图或图片编辑意图后输出结构化标签，系统从 SSE 中
解析并隐藏标签，再复用既有 `generate_image` 工具状态机完成图片调用和第二轮答复。

## 文件变更清单

- `backend/app/services/platform_tools.py`：平台工具协议 Prompt、严格 JSON 解析、
  跨 chunk 流式解析器、平台工具结果摘要和兼容消息回放。
- `backend/app/api/workspace.py`：文本 Provider 请求注入协议、平台调用转换、参考图
  附件元数据和遮罩资产归属校验。
- `backend/tests/test_platform_tools.py`：普通流、任意分片、多标签、非法/不完整标签、
  尺寸与附件协议、平台/原生工具回放测试。
- `backend/tests/test_api.py`：参考图编辑意图的平台工具端到端测试。
- `backend/README.md`、`docs/聊天系统.md`：兼容协议、回放策略和验证状态说明。
- `md/plan-文本模型兼容工具调用-20260902.md`：实施方案和完成状态。

## 核心代码说明

1. 图片工具启用时，文本请求仍发送标准 `tools/tool_choice`，同时在消息首部注入
   `PLATFORM_TOOL_SYSTEM_PROMPT`。普通问答维持原有文本输出；图片意图约定输出
   `<platform_tool_call>{...}</platform_tool_call>`。
2. `PlatformToolStreamParser` 保留可能形成标签的最短后缀，支持开始和结束标签跨任意
   SSE chunk。合法标签不写入 assistant 消息、不发给前端；普通、非法或不完整内容
   保持原样。
3. 当 Provider 没有原生工具调用时，平台标签被转换为内部 `ToolCall`。后续继续使用
   Pydantic 参数白名单、用户资产校验、调用上限、图片资产保存及
   `tool.started/image.created/tool.completed` SSE 事件。原生工具调用始终优先。
4. 真实渠道验证发现其第二轮拒绝 `assistant.tool_calls + role=tool` 并返回 502。平台
   调用采用 `platform-` 保留 ID，下一轮仅将该类历史转换为普通 assistant 请求记录和
   user 结果上下文；原生调用不转换。转换后真实渠道可正常输出最终确认且不会重复生图。
5. 文本消息上传参考图时，Provider 内容附加服务端生成的
   `<platform_attachments>` JSON。模型可以复制真实 `asset_ids/mask_asset_id` 发起编辑，
   执行前仍核验归属、MIME、文件存在性和总大小。
6. Prompt 明确图片尺寸白名单。真实模型曾在未列白名单时返回 `1024x1792`；收紧后
   返回 `1024x1536`，并通过 `GenerateImageToolArguments` 校验。

## 测试验证

- `python -m compileall -q app tests`：通过。
- `pytest -q`：`33 passed`。
- `npm run build`：TypeScript 与 Vite 生产构建通过。
- 目标渠道 `/v1/models`：实时返回 7 个模型入口，其中 6 个文本入口和
  `gpt-image-2` 图片模型。
- 真实两轮 SSE：第一轮 `gpt-5-6-mini` 未返回原生 `tool_calls`，正确输出平台标签；
  标签参数通过 Pydantic 校验。第二轮消息角色为 `system/user/assistant/user`，HTTP
  请求成功并返回“已生成”确认，没有再次输出平台工具标签。
- API 端到端测试：平台标签跨 3 个分片返回，服务端调用带参考图的图片 Provider，
  SSE 出现完整工具/图片事件，协议标签未进入 SSE 或持久化 assistant 正文。

## 待优化项

- 当前兼容协议只开放 `generate_image`；后续增加平台工具时应扩展统一注册表、参数
  Schema 与每个工具的执行器，而不是在 Prompt 和路由内分别硬编码。
- 可在渠道能力中增加显式的工具传输策略，以便管理端按渠道选择 `native`、
  `prompt` 或 `auto`；当前 `auto` 同时发送原生工具和兼容 Prompt。

## 自审修复

- 第一轮自审发现未闭合平台标签只有在流结束后才检查长度。解析器现已在增量追加时
  执行 200,000 字符上限，超限立即按普通文本释放并清空状态；闭合超长标签同样不会
  产生工具调用。
- `GenerateImageToolArguments` 增加 `ConfigDict(extra="forbid")`，与函数 Schema 的
  `additionalProperties: false` 保持一致，未知参数会进入既有失败工具结果流程。
- 新增对应回归后全量测试由 31 项增加至 33 项。
- 第二轮自审结论为“通过（A，无阻断问题）”。
