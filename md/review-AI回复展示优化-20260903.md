��验前推进 Last-Event-ID，半帧断流会跳过关键事件

**位置**

- `src/App.tsx:311-320,379-395`

**问题**

`handle` 在确认 `data` 存在、JSON 可解析且事件已应用之前就更新 `lastEventId`。流结束时，残留 buffer 即使只是半帧也会进入 `handle`。例如 `message.completed` 在 JSON 中间断开时，该事件 ID 已被客户端确认，但 `completed` 仍为 false；重连请求携带该 ID，服务端按 `event_id > cursor` 回放，因此会跳过完整的完成事件。随后客户端可能只收到 `request.usage` 或空回放，最终进入错误清理与重新加载路径，产生“服务端已成功持久化、前端却提示失败”的不一致体验。

**建议**

1. 完成事件名和 data 解析、校验、状态应用后再提交 `lastEventId`。
2. 异常 EOF 的未终止 block 保留给重连，不把其中的 ID 当作已消费；仅在确认这是正常 EOF 且帧完整时处理无尾部分隔符的帧。
3. 增加前端半帧断流测试，分别截断 `message.created`、`message.delta`、`search.started` 和 `message.completed`，断言重连头、最终 UI 内容与持久化消息完全一致。

### P2-1：Markdown 会自动加载模型提供的远程图片，现有安全策略与测试未覆盖该边界

**位置**

- `src/App.tsx:783-794`

**问题**

`skipHtml` 能屏蔽原始 HTML，`react-markdown` 默认 URL transform 也会过滤 `javascript:` 等危险协议，外链同时设置了 `noopener noreferrer`，这些基础措施正确。但当前未限制 Markdown `img`，模型正文中的 `![x](https://HOST/pixel)` 会触发浏览器主动请求第三方资源，带来 IP、Referer 和跟踪像素暴露风险；需求只声明了链接、代码、表格等展示能力，并未要求远程图片直出。

**建议**

禁用 `img`，或经受控资源代理、域名/MIME/大小策略处理后再显示；补充原始 HTML、`javascript:`/`data:` URL、协议相对 URL及远程图片测试。
