## 发现与修复

### 修复：失败图片消息被当作图片渲染

**根因**：直接图片生成的失败分支将助手消息内容写为失败文字，但未把 `content_type` 从 `image` 改为 `text`。历史会话刷新后，前端把这段失败文字当相对 URL 请求；Nginx SPA 回退返回 HTML blob，浏览器最终显示破图。

**后端修复**：

- `backend/app/api/workspace.py`
  - 图片调用失败后将助手消息持久化为 `text`，不再留下无 Asset 的 image 消息。
  - 对上游 403、429 分别给出“未开通生图权限”和“图片配额不足”的稳定用户可见说明；直接图片接口与文本工具生图入口共用这一映射，其余错误使用通用渠道配置提示。

**前端修复**：

- `src/App.tsx`
  - 成功图片消息在内存状态中带上 `asset_id`。
  - 仅在消息确有 Asset 且路径为平台资产或 `data:image/` 时渲染图片预览。
  - 图片资产读取时强制校验响应 MIME，并在图片解码失败时回退为错误提示，避免将 HTML 或其他响应包装为可下载图片。
  - 图片接口失败时解析统一错误响应的 `message` 并直接展示，避免把上游 403 误判为用户授权失效；非用户中止时重新读取服务端持久化的失败消息。
  - 文本工具流的 `tool.completed` 读取并展示后端返回的图片权限/配额说明。
  - 旧的异常 image 记录会回退为文本，不再展示破图。

**新增测试**：

- `backend/tests/test_api.py`：覆盖上游 403 与 429 的直接图片和文本工具图片失败、持久化、SSE/API 提示、无 Asset 与文本消息类型。
- `src/App.test.tsx`：覆盖历史异常 image 记录显示失败文本且不请求/渲染图片、图片接口错误提示与持久化失败记录回读、工具流错误提示、非图片 MIME 回退。

## 外部依赖与待处理项

1. Codex 图片上游对生成/编辑返回 403（当前组未启用生图）；官网图片上游返回 429（无可用图片配额）。平台已正确记录失败，成功生图与成功编辑需待渠道开通权限或补充配额后复验。
2. Codex `gpt-5.2` 使用 high 思考等级在本次公网调用中返回模型请求失败；`gpt-5.6-sol`、`gpt-5.6-terra` 正常，建议在渠道侧检查该模型的高思考支持情况。
3. Nginx 当前只配置 HTTP 80；`https://` 入口 TLS 握手超时，需配置域名、证书和 443 监听后再开放 HTTPS。
4. 文本工具调用中的图片子请求失败时，根文本请求仍可完成并返回模型的失败说明。这一状态表示文本轮次成功、子工具失败；如业务需要将整轮统一标为失败，可另行引入 `completed_with_tool_error` 状态。
