# 模型渠道自动同步实施记录

日期：2026-09-02

## 任务概述

将已验证的 OpenAI-compatible 文本/图片渠道持久化到管理端，并让
`/admin/model-channels` 页面在进入时及此后每 60 秒通过本站后端同步一次远端模型列表。

## 核心实现

1. 页面首次挂载时加载真实渠道列表，对所有 `enabled=true` 渠道并发调用现有
   `/{channel_id}/sync-models`，完成后重新读取渠道列表；`setInterval(60000)` 重复执行。
2. 首次任务通过 `setTimeout(0)` 启动，使 StrictMode 的第一次 setup/cleanup 能先取消
   预演任务。自动与手动调用共享 `useRef<Map<channelId, Promise>>`；同渠道只复用现有
   Promise。组件卸载时清理首次任务、interval 并中止尚未结束的自动 fetch。
3. 自动同步错误不产生每分钟 Toast；服务端保留已有模型并写入 `last_sync_error`，页面
   在渠道行显示失败。管理端手动同步仍即时反馈结果。
4. 同步时间兼容 MySQL `DATETIME` 丢失 UTC 后缀的情况：无时区字符串按 UTC 解析，再
   使用浏览器本地时区显示。
5. 目标渠道通过管理 API 创建为 `both` 模态，显式配置 6 个文本模型和 1 个图片模型
   能力；API Key 仅加密存储于后端，前端响应继续显示掩码。
6. 后端同渠道同步使用进程内 `Condition` 单航班状态；首个请求发布结果并将 active 置为
   false 后原子唤醒全部等待者，等待者复用同一个响应，不重复访问上游。渠道 URL 禁止嵌入
   用户名/密码，Origin 改变时要求重新输入密钥。

## 安全与运维

- 定时请求只访问本站管理 API，上游地址和密钥由后端使用；列表接口只返回掩码密钥。
- 自动同步只处理已启用渠道，停用渠道保留现有模型配置但不产生周期性上游请求。
- 当前同步策略保留远端暂未返回的手工模型别名，避免上游短期波动删除管理员配置。
- 更换 Base URL Origin 时，服务端不把旧密钥带到新地址；管理员必须重新提交新地址密钥。
