# 模型渠道自动同步实施方案

日期：2026-09-02

## 用户原始需求

- 更新 `/admin/model-channels` 页面，把已确认可用的 OpenAI-compatible 渠道接入系统。
- 页面每隔 1 分钟调用渠道接口获取一次最新模型列表。

## 技术方案

1. 复用现有服务端 `POST /api/v1/admin/model-channels/{channel_id}/sync-models`，API Key
   继续只在服务端解密并请求上游 `/v1/models`，浏览器不直接接触密钥。
2. 页面进入后立即执行一次“加载渠道 → 同步所有已启用渠道 → 重新加载渠道”，随后
   每 60 秒重复；首次任务用零延迟定时器规避 React StrictMode 预演重复调用，并使用
   `useRef` 的按渠道 Promise Map 统一防止自动/手动同步重入。
3. 自动同步静默执行，连接错误通过渠道的 `last_sync_error` 展示，避免每分钟重复弹出
   Toast；手动同步继续给出明确通知。
4. 页面显示“每 60 秒自动同步”、同步中状态和最近刷新时间；卸载页面时清理定时器，
   避免后台继续请求。
5. 通过真实管理端 API 创建目标渠道，配置 6 个文本模型与 1 个图片模型的能力映射，
   再调用同步接口确认上游模型列表和数据库状态一致。
6. 保留现有新增、编辑、启停、测试、删除和手动同步能力；新增渠道保存后立即进入下一
   次自动同步范围。
7. 服务端以渠道级 Condition 单航班状态复用并发同步结果；Base URL 拒绝 URL 凭据，且切换 Origin 时必须
   重新提交 API Key，避免把不可见的已存密钥带到新地址。

## 风险与控制

- 多标签页重复请求：页面按渠道防重入；服务端在同步结果发布前保持 active 状态，并一次
  唤醒所有等待者复用该结果。
- 上游响应慢：现有 Provider 模型列表请求使用 8 秒超时，失败只记录状态，不清空已有模型。
- 页面卸载后写状态：定时器清理并以生命周期标记忽略后续 UI 更新。
- API Key 泄漏：浏览器仅调用本站管理 API，渠道响应继续只返回掩码密钥。
- 渠道换源：URL 不接受 userinfo；Origin 改变时不复用存量密钥，要求重新输入。
- 上游临时删除模型：现有同步采用远端模型优先、保留手工别名的合并策略，避免短期波动
  直接移除管理员配置。
