# Chat 图片上传识别方案

## 用户原始需求

当前 `/chat` 页面可以上传图片，但普通文本对话只把图片作为参考资产 ID 发送，文本模型无法读取图片像素。需要参考另一个项目的多模态方案，让用户在不切换图片编辑/生图模式时上传图片，并由文本模型完成识图对话。

## 技术方案设计

采用“上传资产用于持久化，视觉 Data URL 仅用于当前文本请求”的链路：

1. 浏览器继续通过 `/assets/upload` 保存用户图片，并读取本地 `File`。
2. 浏览器将图片缩放到最长边不超过 1600 像素，优先编码为 JPEG Data URL，限制单张和整轮载荷大小。
3. `/threads/{thread_id}/messages/stream` 增加 `media_inputs` 字段，携带 `data_url`、资产 ID、MIME 与尺寸元数据；数据库只保存资产 ID 和元数据，不保存 Base64 像素。
4. 后端校验 Data URL、Base64、图片文件头、单张/总大小和资产归属；文本流的最后一条用户消息使用临时视觉输入。
5. OpenAI Chat Completions 转换为 `image_url` + `text`，Responses 转换为 `input_image` + `input_text`，保留现有工具调用和流式逻辑。
6. 前端显示待发送缩略图，发送后在用户消息中保留资产缩略图；普通文本模型继续走文本模型选择器，图片模式不受影响。

自动模型选择时，若线程保存的历史模型是文本专用或已失效，服务端按渠道优先级寻找视觉文本模型；显式选择模型/渠道仍保持严格路由。
