# ChatGPT 对话系统实施方案

日期：2026-08-28  
版本：v2（根据计划评审修订）

## 1. 用户原始需求

基于当前已完成的 ChatGPT 官网对话页前端复刻，建设一套可实际提供用户聊天对话的系统：

- 用户可以注册、登录，点击“开始使用”进入聊天页。
- 聊天页支持直接新建对话，也支持新建项目并在项目内创建多个对话。
- 用户可以发起文本聊天、图片生成等请求，按不同模型路由到文本模型或图片模型。
- 每个用户的项目、对话、消息和生成记录隔离存储。
- 用户可以导出自己的对话内容。
- 管理端可以管理用户、开通/撤销使用权限并设置授权期限，例如按月授权。
- 管理端可以查看用户模型调用记录、输入 token、输出 token；token 统计先预留数据字段，后续再接入真实采集逻辑。
- 后端采用 Python。

本阶段输出实施计划，不进入功能编码。现有 `src/App.tsx` 和 `src/styles.css` 作为聊天页视觉与交互基线直接复用。

## 2. 当前基础与边界

- React 18 + TypeScript + Vite 工程位于当前根目录。
- `src/App.tsx` 已有侧边栏、最近会话、项目/功能入口、消息区、流式光标、附件菜单、分享、归档、删除、重新生成和响应式抽屉。
- `src/styles.css` 已完成桌面端和移动端 ChatGPT 风格布局。
- `public/avatar.png`、`public/favicon.svg` 和 `reference/chat-page-reference.png` 已存在。
- 当前聊天、项目入口和模拟回复使用 React 本地状态，未接入账号、持久化或模型服务。

### 2.2 本阶段边界

- 复用现有页面结构和样式，不重新设计聊天页视觉。
- 首期后端只提供业务数据、鉴权、模型调用编排和权限校验；具体供应商密钥通过服务端环境变量管理。

- 不复制目标网站源代码或服务端逻辑，不接入真实 ChatGPT 账号数据。

## 3. 总体技术方案

### 3.1 架构

```text
React/Vite 前端
  ├─ 公共认证页（注册/登录/开始使用）
  ├─ ChatGPT 风格聊天工作区
  └─ 管理端路由与数据表格
          │ REST/JSON + SSE 流式响应
FastAPI（Python）
  ├─ JWT 鉴权、RBAC、授权期限校验
  ├─ 用户/项目/对话/消息/导出 API
  ├─ 模型适配器（文本/图片）
  └─ 使用记录与管理 API
          │
MySQL 8（业务持久化）
Redis（限流、任务状态，可选）
文件存储（首期本地卷，生产可切换 S3 兼容存储）
```

### 3.2 技术选型

- 后端：Python 3.12、FastAPI、Pydantic v2、SQLAlchemy 2.x async、Alembic。
- 数据库：MySQL 8；当前本地使用 `chat_workspace` 数据库，SQLAlchemy 通过 PyMySQL 连接。
- 鉴权：短时效 access JWT + refresh token；密码使用单向哈希，不保存明文（当前 Conda 开发环境采用标准库 PBKDF2-SHA256，生产可切换 Argon2id）。
- 流式：聊天接口使用 SSE，前端逐块更新已有消息；图片生成返回任务状态和图片资源 URL。
- 模型：定义统一 `TextModelProvider` / `ImageModelProvider` 接口，首期接入一个 OpenAI-compatible 适配器，后续可增加其他供应商。
- 前端：继续使用 React + TypeScript + lucide-react；增加 React Router（或轻量路由层）和 API client，不替换现有 CSS 体系。
- 测试：后端 pytest + httpx，前端 TypeScript 构建和关键交互测试；端到端使用 Playwright（环境可用时）。

## 4. 领域模型与数据隔离

所有业务表带 `user_id` 或可追溯的项目归属，并在 Service 层统一校验当前用户身份。建议表结构如下：

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `users` | `id`, `email`, `password_hash`, `display_name`, `role`, `status`, `created_at` | 用户与管理员账号 |
| `refresh_tokens` | `id`, `user_id`, `token_hash`, `expires_at`, `revoked_at` | 刷新令牌轮换 |
| `entitlements` | `id`, `user_id`, `starts_at`, `expires_at`, `status`, `granted_by` | 使用权限和期限 |
| `projects` | `id`, `user_id`, `name`, `description`, `archived_at` | 用户项目 |
| `threads` | `id`, `user_id`, `project_id`, `title`, `model`, `status`, `archived_at` | 直接会话或项目会话 |
| `messages` | `id`, `thread_id`, `user_id`, `role`, `content`, `content_type`, `sequence`, `created_at` | 文本、图片结果和附件引用 |
| `model_requests` | `id`, `user_id`, `thread_id`, `message_id`, `model`, `modality`, `status`, `input_tokens`, `output_tokens`, `provider_request_id`, `latency_ms`, `error_code` | 每一次模型调用；token 字段允许为空 |
| `model_channels` | `id`, `name`, `provider`, `protocol`, `base_url`, `api_key_encrypted`, `modality`, `enabled`, `priority`, `models_json`, `created_by`, `created_at`, `updated_at` | 管理端配置文本/图片模型渠道；首期协议固定支持 OpenAI-compatible |
| `assets` | `id`, `user_id`, `message_id`, `kind`, `storage_key`, `mime_type`, `size_bytes` | 上传附件和生成图片 |
| `exports` | `id`, `user_id`, `thread_id`, `format`, `status`, `storage_key`, `expires_at` | 导出任务与下载地址 |
| `admin_audit_logs` | `id`, `admin_id`, `action`, `target_user_id`, `metadata`, `created_at` | 管理端授权、禁用、撤销记录 |

关键约束：

- `users.email` 唯一；`projects(user_id, name)` 可按业务决定是否唯一。
- 所有查询默认附带当前用户条件，管理员接口单独走 RBAC 权限。
- `threads.project_id` 可为空，表示直接新建对话；项目删除时采用软删除或禁止存在活跃会话的硬删除。
- 消息采用有序序列；流式过程中先写入 assistant 草稿消息，结束时写入最终状态。
- `input_tokens`、`output_tokens` 使用整数可空字段，并保留供应商原始 usage JSON，便于后续补采集。

## 5. API 设计

### 5.1 认证

- `POST /api/v1/auth/register`：邮箱、密码、显示名称注册。
- `POST /api/v1/auth/login`：返回 access token 和 refresh token。
- `POST /api/v1/auth/refresh`：轮换刷新令牌。
- `POST /api/v1/auth/logout`：撤销当前刷新令牌。
- `GET /api/v1/me`：返回当前用户资料、角色和当前授权状态。

### 5.2 项目与对话

- `GET/POST /api/v1/projects`：项目列表、新建项目。
- `PATCH/DELETE /api/v1/projects/{project_id}`：修改、归档项目。
- `GET/POST /api/v1/threads`：会话列表、新建直接会话或项目会话。
- `GET/PATCH/DELETE /api/v1/threads/{thread_id}`：会话详情、重命名、归档/删除。
- `GET /api/v1/threads/{thread_id}/messages`：分页读取消息。
- `POST /api/v1/threads/{thread_id}/messages/stream`：文本聊天，SSE 事件包括 `message.created`、`message.delta`、`message.completed`、`request.usage`、`error`。
- `POST /api/v1/threads/{thread_id}/image-generations`：图片生成，返回任务 ID、状态和生成资源。
- `POST /api/v1/threads/{thread_id}/regenerate`：重新生成指定 assistant 消息。

### 5.3 资源与导出

- `POST /api/v1/assets/presign`：获取上传地址（首期可直接 multipart 上传）。
- `GET /api/v1/threads/{thread_id}/export?format=json|markdown|txt`：创建导出任务。
- `GET /api/v1/exports/{export_id}`：查询导出状态和短期下载地址。

### 5.4 管理端

- `GET /api/v1/admin/users`：分页、搜索、状态筛选。
- `GET /api/v1/admin/users/{user_id}`：用户详情、当前授权和汇总用量。
- `POST /api/v1/admin/users/{user_id}/entitlements`：按起止时间或月数开通权限。
- `PATCH /api/v1/admin/entitlements/{entitlement_id}`：暂停、撤销或调整期限。
- `GET /api/v1/admin/usage`：按用户、模型、时间范围查询请求记录及 token 字段。
- `GET /api/v1/admin/audit-logs`：查询管理操作审计记录。
- `GET /api/v1/admin/model-channels`：分页读取模型渠道，支持按模态和启用状态筛选；API Key 只返回掩码。
- `POST /api/v1/admin/model-channels`：创建文本或图片模型渠道，协议支持 `openai`，配置 Base URL、API Key、模型列表和优先级。
- `PATCH /api/v1/admin/model-channels/{channel_id}`：修改渠道、启停渠道、更新密钥或模型列表。
- `DELETE /api/v1/admin/model-channels/{channel_id}`：删除渠道（有请求记录时改为停用）。
- `POST /api/v1/admin/model-channels/{channel_id}/test`：使用配置向 OpenAI-compatible `/models` 或最小请求探测连通性，不返回密钥。

统一响应约定：错误返回 `{code, message, request_id, details}`；所有写接口支持幂等键或客户端 request id，避免重试造成重复消息/授权。

## 6. 前端复用与页面拆分

### 6.1 保留并改造现有聊天页

- 保留 `src/styles.css` 的布局、颜色、间距、响应式断点和图标风格。
- 将 `src/App.tsx` 拆为 `layouts/ChatLayout`、`components/Sidebar`、`components/ConversationView`、`components/Composer`、`components/WorkspacePage`、`components/ShareDialog`。
- 将本地 `threads`、`archivedThreads`、`defaultThreads` 替换为 `useProjects`、`useThreads`、`useMessages` 数据 hooks。
- `send()` 改为创建用户消息并消费 SSE；流式 delta 直接更新 assistant 消息，完成后刷新用量状态。
- 附件按钮接入资源上传；图片模型入口使用模型选择器或模式选择，不破坏现有输入器布局。
- 保留模拟数据开关，便于无后端时预览页面。

### 6.2 新增认证和管理页面

- `pages/LandingPage`：开始使用按钮，未登录跳转登录。
- `pages/LoginPage`、`pages/RegisterPage`：表单校验、错误提示、登录后回跳。
- `pages/AdminUsersPage`：用户表格、搜索、状态、授权弹窗。
- `pages/AdminUsagePage`：模型请求记录、输入/输出 token、状态和时间筛选。
- `components/ProtectedRoute`：登录态、管理员角色和授权期限拦截。
- `lib/api.ts`、`lib/auth.ts`、`lib/sse.ts`：统一请求、令牌刷新、SSE 解码。

### 6.3 用户体验规则

- 无有效授权时允许登录和查看历史，但发送/生成按钮显示权限提示并禁止提交。
- 会话、项目和导出按钮在请求期间有明确 loading/disabled 状态。
- 断线后支持从最后一个事件 ID 继续或提示重试，避免重复插入消息。
- 导出下载仅允许当前用户访问自己的导出记录，链接设置短期过期时间。

## 9. 安全、可靠性与运营要求

- 密码仅存哈希；JWT 密钥、模型供应商密钥和数据库密码只从环境变量读取。
- API 对登录、注册、模型调用和导出接口做 IP/用户级限流。
- 所有资源访问校验 `user_id`；管理员操作记录审计日志。
- 模型请求设置超时、最大输入长度和单用户并发上限；失败时不将供应商原始错误直接暴露给用户。
- SSE 连接断开时释放模型流和数据库事务；后台任务可重试但必须幂等。
- 记录 request id、模型、耗时、状态和错误码，敏感提示词按部署策略脱敏或限制日志内容。
- 首期 token 字段允许为空；补齐供应商 usage 后通过异步回填，不修改消息正文。

## 10. 验收标准

### 用户端

- 新用户可以注册、登录并进入聊天页；未登录访问聊天页会跳转登录。
- 用户可以创建项目、在项目内创建对话、直接创建对话、切换/归档/删除/恢复。
- 文本请求通过 SSE 流式显示，刷新页面后项目、对话和消息仍存在。
- 图片请求能显示生成中、成功、失败三种状态，并能查看/下载结果。
- 用户只能看到自己的项目、对话、消息、资源和导出文件。
- 支持 JSON、Markdown 或 TXT 至少一种导出格式，导出内容与当前会话一致。

### 管理端

- 管理员可以搜索用户、查看状态和授权到期日。
- 管理员可以按月或指定日期开通、暂停、撤销使用权限。
- 管理员可以按用户/模型/时间查看请求记录和 token 字段，即使 token 暂为空也能正常展示。
- 非管理员无法访问管理端接口和页面；管理操作可追溯。

### 工程质量

- `npm run build` 通过；Python lint、类型检查和 pytest 通过。
- 数据库迁移可从空库完整执行；服务可通过 `.env.example` 启动。
- 关键 API 有自动化测试，越权访问、授权过期和重复提交均有覆盖。

## 11. 风险与待确认项

| 风险/决策 | 默认处理 |
| --- | --- |
| 模型供应商未确定 | 先实现 OpenAI-compatible Provider，供应商通过配置切换 |
| token 统计来源未确定 | 字段可空并保存原始 usage，后续按 Provider 补齐 |
| 图片生成耗时较长 | 首期同步/短任务兼容，超过阈值转后台任务 |
| 文件存储位置未确定 | 开发使用本地卷，生产抽象为 S3 兼容存储 |
| 邮箱验证/找回密码未要求 | 首期预留字段和路由，不阻塞注册登录主流程 |
| 部署环境未确定 | 提供本地 Docker Compose，部署方式后续按环境补充 |
