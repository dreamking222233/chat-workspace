# 模型提供商接入实施记录

日期：2026-08-31

## 任务概述

为聊天工作区接入多个 OpenAI-compatible 模型渠道，覆盖文本流式对话、图片生成、
参考图编辑，以及文本模型自主调用 `generate_image` 工具的多回合流程。

  渠道能力和同步状态字段。

## 核心实现

1. 渠道 Base URL 规范化为 API 根路径，按优先级和模型能力选择文本或图片渠道。
2. 文本请求默认使用 Chat Completions SSE；可选 Responses transport 会转换输入、
   函数工具并解析 `response.output_text.delta` 等事件。
3. 文本流消费完一轮后合并 `tool_calls`。每个 `generate_image` 调用先验证参数、
   用户资产归属和文件大小，再调用图片 Provider，保存生成资产并发出：
   `tool.started`、`image.created`、`tool.completed`。工具结果作为下一轮输入，
   回合/调用数受配置限制。
4. 图片模式无参考图走 `/images/generations`，有参考图或 mask 走 multipart
   `/images/edits`；生成结果和请求用量写入数据库，资源通过用户令牌访问。
5. 内部 `tool_call`/`tool` 消息保留结构化数据用于重放和审计，但线程、消息和导出
   接口只返回用户可见内容；参考图只随当前图片草稿发送，切换会话或完成生成后清理。

## 运维注意

- 生产先备份数据库，再执行 Alembic；部署环境设置独立的
  `CHAT_ENCRYPTION_KEY` 和 `CHAT_MODEL_CHANNELS_JSON`。
- 管理端创建渠道后点击“同步模型”，必要时在能力映射中保留图片模型标记；
  上传参考图总大小受 `CHAT_MODEL_MAX_REFERENCE_BYTES` 限制。

## 收尾修复（2026-08-31）

- 图片请求发生幂等竞争时清理未获胜的用户/助手占位消息，避免重复提示词；
  Provider 抛出 HTTPException 时也会将图片请求收敛为失败状态。
- 重新生成请求在前端透传所选 `channel_id`，同名模型不会回落到优先级渠道。
- 文档补充上游 `/models`、Chat Completions、Responses、图片生成/编辑的字段与
  SSE 事件契约，并注明图片资源采用 Authorization Blob 加载。
- 重新生成请求在进程重启/并发幂等重放前先查询数据库根请求，避免清空既有 assistant
  内容；竞争失败方不再删除胜者复用的 assistant 行，并新增回归测试。
- 管理端渠道编辑器新增 JSON 能力映射字段，可直接标注文本/图片模型并选择
  Responses 或 JSON 图片编辑传输；服务端保留特殊传输键的白名单。
- 图片响应解析补充 `data` Base64 别名与 HTTP 200 JSON 错误帧处理。
