# 图片生成参数与状态实施方案

## 用户原始需求

- 图片生成已经可用，但生成期间需要呈现接近 ChatGPT 官网的“正在创建图片”占位卡片，而不是只显示普通等待圆点。
- 用户可在自然语言中描述图片参数，例如“生成一张抖音直播间截图 16:9 2K 高清”，系统需要把比例、分辨率和质量要求转换为图片接口参数并实际下传。
- 图片生成完成后继续提供大图预览、下载和消息操作；图片编辑与文本模型触发的 `generate_image` 工具复用相同参数规则。

## 技术方案设计

### 1. 参数解析与校验

- 新增纯函数图片参数解析模块，统一处理中文/英文、全角/半角写法。
- 从 Prompt 提取常见比例（如 `1:1`、`16:9`、`9:16`、`4:3`、`3:4`）、分辨率等级（`2K`、`4K`、`1080P`、`720P`）和质量描述（`高清`、`高质量`、`high` 等）。
- 示例映射：按当前渠道页面预设，`16:9 + 2K -> 2560x1440`，`高清 -> quality=high`；正方形 2K 使用 `2048x2048`。
- 保留 `auto` 和旧 OpenAI-compatible 固定尺寸，同时允许当前渠道支持的有界 `WIDTHxHEIGHT` 尺寸，避免现有枚举阻止 `2560x1440`、`1920x1080` 等参数。
- 显式 Prompt 指令优先于请求默认值；未识别到指令时保留调用方参数或使用 `auto`。

依据：官方 OpenAI 图片生成文档列出 `size`、`quality` 等输出配置，并说明 `gpt-image-2` 支持自定义尺寸以及 `low/medium/high/auto` 质量值：
https://developers.openai.com/api/docs/guides/image-generation

当前渠道的 `/openapi.json` 也确认 `/v1/images/generations` 接收 `size`、`quality`、`n` 和 `response_format`。

### 2. 调用链路接入

- 直接图片模式：`ImageGenerationRequest` 在服务端解析 Prompt 后，将有效 `size/quality` 传给 Provider。
- 图片编辑：复用同一解析流程并继续携带参考图、遮罩图。
- 文本模型工具：扩展原生 Function schema 与平台 System Prompt，明确参数格式和 `16:9 + 2K` 示例；工具参数在执行前再次通过确定性解析器规范化。
- Provider 继续按 OpenAI-compatible 协议调用 `/images/generations` 或 `/images/edits`。

### 3. 前端生成状态与结果展示

- 发送图片请求时把助手占位消息标记为图片生成中。
- 增加“正在创建图片”大尺寸圆角卡片，使用 CSS 点阵渐变与呼吸动画模拟官网生成效果。
- 文本工具进入 `generate_image` 时也切换到图片生成卡片；图片创建事件到达后替换为实际图片，后续文本仍正常流式显示。
- 放大最终图片预览区域并保持原始宽高比；保留下载、复制、评价、分享和重新生成操作。
- `prefers-reduced-motion` 下停用动画但保留清晰占位状态。

## 涉及文件清单

- `backend/app/services/image_options.py`：自然语言参数解析与尺寸/质量校验。
- `backend/app/schemas/common.py`：图片请求与工具参数校验。
- `backend/app/services/platform_tools.py`：平台工具提示词。
- `backend/app/api/workspace.py`：直调和工具调用接入解析结果。
- `backend/tests/test_image_options.py`：参数解析单元测试。
- `backend/tests/test_providers.py`、`backend/tests/test_api.py`：参数下传与工具链路回归。
- `src/App.tsx`：图片占位消息状态、SSE 工具状态、结果渲染。
- `src/styles.css`：图片生成卡片、点阵动画与结果布局。
- `src/App.test.tsx`：生成占位状态回归。
- `docs/聊天系统.md`、`backend/README.md`：参数规则和 UI 状态文档。

## Review 后方案收敛

- 图片消息结构当前只支持单张持久化，公开请求合同固定为 `n=1`。
- `standard/hd` 作为旧客户端输入兼容值，进入 Provider 前分别转换为 `medium/high`。
- 直接生图和文本工具生图都在保存结果前锁定并复核 `ModelRequest`；已停止的迟到结果不落盘。
- 测试默认使用独立临时 SQLite 与资源目录，不再依赖开发机 MySQL。
