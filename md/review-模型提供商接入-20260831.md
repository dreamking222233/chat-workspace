# 模型提供商接入实现审查

审查对象：`md/plan-模型提供商接入-20260830.md`、`md/impl-模型提供商接入-20260831.md` 及当前代码。

## 发现（按严重性）

首轮审查发现的问题已在本轮迭代处理；以下保留问题背景、修复位置和剩余边界，
便于后续回归。

### P1（已修复）：供应商图片 URL 可造成服务端任意出站请求

- `backend/app/services/providers.py:438-462` 对供应商返回的 URL 直接执行 `httpx.stream("GET", url)`；`_parse_image_response` 在 `:483-488` 无域名、scheme、解析后 IP 或响应 MIME 的限制。
- 渠道响应可指向内网地址、云元数据地址或本机服务，API 会替供应商读取并把内容保存为用户资产。`follow_redirects=False` 只限制重定向，未覆盖首跳目标。
- 修复：`providers.py` 现在校验 scheme、凭据、渠道 host 白名单、DNS 解析地址、
  HTTP 开关、重定向关闭、Content-Length、实际 MIME 和总字节数；允许显式配置
  `image_url_hosts`/私网测试开关。

### P1（已修复）：文本流幂等键只在进程内，且并发请求可重复计费

- `backend/app/api/workspace.py:393-414` 通过 `idempotency_requests` 内存字典解析重放；`backend/app/api/workspace.py:450-463` 先创建 `ModelRequest`，随后才写入该字典。
- 多 worker、进程重启或两个相同 `Idempotency-Key` 并发到达时，数据库没有唯一约束或原子查重，会创建多条根请求并重复调用文本/图片渠道。迁移 `0002_model_provider_features.py:39-43` 建立的是普通索引。
- 修复：`0003_request_events` 增加组合唯一索引，路由使用进程锁和数据库查重；
  事件写入 `ModelRequest.events_json`，跨 worker/重启可按事件游标重放。极端跨库
  并发仍应依赖数据库唯一索引错误处理。

### P1（已修复）：数据库重放把失败或进行中的请求伪装成完成

- `backend/app/api/workspace.py:415-431` 在内存 `StreamState` 不存在时，无条件发出 `message.completed` 和 `request.usage`，未检查 `ModelRequest.status`，也没有重放 `error` 或 `stopped` 事件。
- 进程重启或跨 worker 重连到 `running` 请求时，客户端会收到终态并停止等待；重连到 `failed`/`stopped` 请求时，前端会把它当作正常完成。该行为与方案要求的断线恢复和终态一致性不符。
- 修复：`_resume_stream` 按 `completed`、`failed`、`stopped` 发送对应事件，
  `running` 且无活动状态时返回冲突；已落库事件优先按 `Last-Event-ID` 重放。

### P1（已修复）：前端丢弃 `channel_id`，同名模型始终落到优先级渠道

- 后端 `/models` 返回 `channel_id`（`backend/app/services/models.py:56-65`），但 `src/App.tsx:124,168,592` 的状态类型和 `<select>` 只保存/提交 `model`。
- 相同模型 ID 出现在多个渠道时，`choose_channel`（`backend/app/services/models.py:41-48`）总是按优先级选渠道；用户选择的渠道名称只用于 option key，实际请求没有携带它，线程历史也只保存模型字符串。
- 修复：模型选择器使用 `channel_id::model` 稳定值，文本/图片/重新生成请求
  透传 `channel_id`；服务端验证渠道启用状态、模型归属和模态能力。

### P1（已修复）：图片 Base64 响应在限额前完整解码，存在内存耗尽路径

- `backend/app/services/providers.py:416-435` 调用 `base64.b64decode` 前没有大小检查；`_parse_image_response`（`:475-488`）随后直接返回内容，`_persist_image_asset`（`backend/app/api/workspace.py:236-245`）也没有输出大小上限。
- 供应商返回超大 `b64_json` 时，解码和数据库前的文件写入会消耗大量内存/磁盘。现有 25 MiB 限制仅覆盖 URL/data URL 下载，不覆盖 Base64 分支。
- 修复：Base64 长度在解码前按 4/3 比例预检，Provider 和资产落盘两层均受
  `CHAT_MODEL_MAX_IMAGE_BYTES` 限制，超限会记录失败请求。

### P2（已修复）：Base URL 含 query/fragment 时端点拼接错误

- `backend/app/services/providers.py:17-32` 保留了 `urlsplit` 的 query 和 fragment，再把 `/models`、`/chat/completions` 等路径追加到完整字符串。例如 `https://HOST/v1?x=1` 生成 `https://HOST/v1?x=1/models`，请求路径实际仍是 `/v1`。
- `AnyHttpUrl` 允许这类输入，管理端保存和测试均未拦截，导致渠道测试成功判定与真实调用路径不一致。
- 修复：Base URL 规范化时丢弃 query/fragment，并增加契约测试，端点拼接保持在
  API 根路径下。

### P2（已修复）：参考资产状态跨线程和跨模式残留

- `src/App.tsx:126,420-423,430` 将 `referenceAssets` 作为全局状态；切换线程、完成图片请求或切换回文本模式后未清空。普通文本发送仍把这些 ID 放入 `asset_ids`。
- 后端 `backend/app/api/workspace.py:193-200` 会把资产 ID 作为 system 消息发送给文本模型，但没有发送图片内容，模型收到的是无语义的内部 ID；用户下一次文本请求还会意外携带上一次图片引用。
- 修复：前端切换线程/退出图片模式/成功生成后清理参考图，仅图片请求提交
  `asset_ids`；文本请求不再注入无语义的内部 ID。

### P2（已修复）：资产访问令牌放在图片 URL 查询串

- `src/App.tsx:631-635` 将长期有效的 JWT 追加到 `<img>` 和下载链接 URL；`backend/app/api/dependencies.py:33-47` 接受该 query token。
- URL 会进入浏览器历史、代理访问日志和复制内容，令牌泄露后可在有效期内读取该用户的所有资产。
- 修复：前端通过带 `Authorization` 的 blob fetch 创建临时 object URL，下载和预览
  不再拼接 JWT 查询参数；后端补充 `Referrer-Policy: no-referrer`，并保留旧查询
  token 兼容路径。

## 测试与残余风险

当前 `pytest -q`（22 passed）和 `npm run build` 通过；手工验证覆盖文本工具
回合、图片编辑、资产越权、持久化重放、幂等重试和渠道精确选择。仍建议在生产
接入前补充真实 Responses SSE、DNS 重绑定和多进程压力测试。

  已完成的 assistant 回复。
- 管理端已补充能力映射编辑与 JSON 传输开关，覆盖未在 `/models` 广告模态能力的
  渠道；前后端构建回归通过。
